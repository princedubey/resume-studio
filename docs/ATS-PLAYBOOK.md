# ATS playbook (Senior Software Engineer)

No checker can guarantee a universal “100 ATS score.” Healthy target after tailoring is often **~75–90+**. Then apply.

## What raises parse / match scores

1. **Single column**, plain text contact in the body (not header/footer only).
2. **Standard headings:** Professional Summary, Skills, Work Experience, Projects, Education, Certifications.
3. **Keywords from the job description** you truly have — in Skills **and** mirrored in bullets.
4. **Consistent dates** (`Jun 2025 – Present`), reverse chronological.
5. **Quantified bullets:** action + scope + metric (latency %, cost %, uptime, APIs integrated).
6. **Acronyms once expanded:** Kubernetes (K8s), CI/CD (Continuous Integration / Continuous Delivery), RAG (Retrieval-Augmented Generation).
7. **Title alignment:** use market title “Senior Software Engineer” when it matches your level.
8. **File type:** follow the posting (often **DOCX**; text-based PDF if allowed).

## What lowers scores

- Two-column layouts, tables, text boxes, icons, images, skill bars  
- Creative section names (“My Journey”)  
- Keyword stuffing tools you cannot defend in interview  
- Missing email/phone/location  
- Vague bullets with no stack and no outcome  

## Apply workflow

1. Paste the JD; highlight required skills/practices.  
2. Duplicate your ATS 2-page resume; rename for that company.  
3. Mirror required terms in Skills + top bullets for recent roles.  
4. Export DOCX/PDF as requested; run one ATS checker; fix parse flags.  
5. Stop chasing 100 — apply when structure + keywords are solid.

## Templates in Resume Studio

| Template | Use when |
| --- | --- |
| `ats-onepage` | Short listing / strict 1-page |
| `ats-twopage` | Senior depth, projects, certs (recommended for most SWE roles) |
| `prince` | Visual human review; prefer ATS versions for portal upload |
